# Техническое задание на реализацию системы бекапов для Obsidian Linker

## 1. Общее описание

Система бекапов для Obsidian Linker предназначена для создания резервных копий файлов перед вставкой автоматически найденных связей. Это позволит пользователю откатить изменения в случае необходимости или при возникновении ошибок.

## 2. Функциональные требования

### 2.1. Создание бекапов
- Автоматическое создание бекапа перед каждым запуском вставки связей в файлы
- Копирование всех файлов, в которые будут вставлены связи
- Сохранение бекапов в отдельной директории с временной меткой

### 2.2. Хранение бекапов
- Создание отдельной директории для бекапов (например, `backups`)
- Использование временной метки в названии директории бекапа (формат: `YYYY-MM-DD_HH-mm-ss`)
- Сохранение структуры директорий из оригинального хранилища в бекапе

### 2.3. Восстановление из бекапа
- Возможность восстановления файлов из бекапа через веб-интерфейс
- Отображение списка доступных бекапов с датами создания
- Подтверждение перед восстановлением из бекапа

### 2.4. Управление бекапами
- Возможность просмотра содержимого бекапа
- Возможность удаления старых бекапов для освобождения места

## 3. Нефункциональные требования

### 3.1. Производительность
- Минимизация времени создания бекапов
- Эффективное использование дискового пространства
- Оптимизация копирования файлов (использование hardlinks где возможно)

### 3.2. Надежность
- Проверка целостности бекапов
- Обработка ошибок при создании и восстановлении бекапов
- Логирование операций с бекапами

### 3.3. Безопасность
- Валидация путей к файлам для предотвращения path traversal атак
- Проверка прав доступа к файлам перед копированием

## 4. Архитектура системы бекапов

### 4.1. Компоненты системы
- BackupManager - основной класс для управления бекапами
- BackupStorage - класс для хранения и организации бекапов на диске
- BackupRestore - класс для восстановления файлов из бекапа

### 4.2. Интеграция с существующими модулями
- Интеграция с LinkInserter для автоматического создания бекапов перед вставкой связей
- Интеграция с веб-интерфейсом для управления бекапами

### 4.3. Формат хранения бекапов
```
backups/
├── 2023-10-15_14-30-22/
│   ├── vault/
│   │   ├── note1.md
│   │   ├── folder1/
│   │   │   └── note2.md
│   │   └── folder2/
│   │       └── note3.md
│   └── backup.json (метаданные бекапа)
├── 2023-10-15_15-45-10/
│   ├── vault/
│   │   ├── note1.md
│   │   └── note4.md
│   └── backup.json
└── backups.json (список всех бекапов)
```

## 5. API для работы с бекапами

### 5.1. Создание бекапа
```
POST /api/backups/create
Content-Type: application/json

{
  "files": ["/path/to/file1.md", "/path/to/file2.md"],
  "vaultPath": "/path/to/vault"
}
```

Ответ:
```json
{
  "success": true,
  "backupId": "2023-10-15_14-30-22",
  "message": "Backup created successfully"
}
```

### 5.2. Получение списка бекапов
```
GET /api/backups/list
```

Ответ:
```json
{
  "backups": [
    {
      "id": "2023-10-15_14-30-22",
      "createdAt": "2023-10-15T14:30:22Z",
      "fileCount": 15,
      "size": 1024000
    },
    {
      "id": "2023-10-15_15-45-10",
      "createdAt": "2023-10-15T15:45:10Z",
      "fileCount": 8,
      "size": 512000
    }
  ]
}
```

### 5.3. Восстановление из бекапа
```
POST /api/backups/restore
Content-Type: application/json

{
  "backupId": "2023-10-15_14-30-22"
}
```

Ответ:
```json
{
  "success": true,
  "message": "Files restored successfully"
}
```

### 5.4. Удаление бекапа
```
DELETE /api/backups/{backupId}
```

Ответ:
```json
{
  "success": true,
  "message": "Backup deleted successfully"
}
```
