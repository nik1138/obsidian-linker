# Техническое задание на разработку веб-интерфейса для Obsidian Linker

## 1. Общее описание

Веб-интерфейс для Obsidian Linker должен предоставлять пользователю графический способ настройки и запуска процесса анализа хранилища Obsidian, а также вставки найденных связей в заметки. Интерфейс должен включать все функции, доступные через CLI.

## 2. Функциональные требования

### 2.1. Настройка параметров анализа
- Указание пути к хранилищу Obsidian
- Настройка порога схожести (0-1)
- Настройка максимального количества ссылок на заметку
- Включение/выключение корректировки для файлов с низким количеством связей
- Включение/выключение инкрементального анализа
- Включение/выключение очистки кэша перед анализом
- Включение/выключение подробного вывода (для отладки)

### 2.2. Запуск анализа
- Кнопка запуска анализа с текущими параметрами
- Отображение прогресса выполнения
- Отображение результатов анализа (количество обработанных файлов, найденных связей и т.д.)
- Возможность сохранения результатов в файл

### 2.3. Настройка параметров вставки связей
- Указание пути к файлу с результатами анализа
- Настройка заголовка раздела связей
- Выбор критерия группировки связей (файл, схожесть)
- Ограничение количества связей на файл
- Включение/выключение подробного вывода (для отладки)

### 2.4. Вставка связей
- Кнопка запуска вставки связей с текущими параметрами
- Отображение прогресса выполнения
- Отображение результатов вставки

### 2.5. Удаление вставленных связей
- Возможность удаления ранее вставленных связей

## 3. Нефункциональные требования

### 3.1. Пользовательский интерфейс
- Чистый, интуитивно понятный интерфейс
- Адаптивный дизайн для различных размеров экранов
- Поддержка темной и светлой тем

### 3.2. Производительность
- Быстрый отклик на действия пользователя
- Эффективная обработка больших объемов данных
- Минимизация использования ресурсов системы

### 3.3. Безопасность
- Валидация пользовательского ввода
- Защита от потенциально опасных операций с файлами

## 4. Архитектура веб-интерфейса

### 4.1. Технологии
- Frontend: HTML, CSS, JavaScript (возможно использование фреймворка)
- Backend: Node.js (использование существующего кода проекта)
- Сервер: Express.js или аналогичный фреймворк

### 4.2. Структура приложения
- Главная страница с настройками анализа и кнопкой запуска
- Страница с настройками вставки связей
- Страница отображения результатов
- Страница управления бекапами (после реализации функциональности бекапов)

### 4.3. Интеграция с основным приложением
- Использование существующих модулей (VaultReader, NLPProcessor, LinkFinder, CacheManager, LinkInserter)
- Создание API endpoints для взаимодействия с фронтендом
- Обработка асинхронных операций с отображением прогресса

## 5. План реализации

### 5.1. Этап 1: Создание базового веб-сервера
- Настройка Express.js сервера
- Создание базовой структуры страниц
- Интеграция с существующими модулями проекта

### 5.2. Этап 2: Реализация функциональности анализа
- Создание формы настройки параметров анализа
- Реализация API endpoint для запуска анализа
- Создание страницы отображения результатов

### 5.3. Этап 3: Реализация функциональности вставки связей
- Создание формы настройки параметров вставки
- Реализация API endpoints для вставки и удаления связей
- Интеграция с системой бекапов

### 5.4. Этап 4: Доработка интерфейса
- Добавление стилей и улучшение UX
- Реализация адаптивного дизайна
- Добавление поддержки темной/светлой темы
